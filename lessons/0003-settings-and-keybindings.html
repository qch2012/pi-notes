Lesson 0003 · Core workflow

Settings and keybindings

Two plain JSON files control almost everything about how Pi behaves and feels: settings.json for behavior, keybindings.json for input. Both are editable by hand or through in-app commands, and both apply live with /reload.

Why this lesson Closes out the mission's "session management ... and settings" fluency target. This is also where a lot of daily-driver friction gets resolved — theme, tool defaults, model defaults, and how aggressively context gets compacted are all one JSON edit away.

1. Where settings live

FileScope
~/.pi/agent/settings.jsonGlobal — applies to all projects
.pi/settings.jsonProject — overrides global, only loaded once the project is trusted (Lesson 0004)

Project settings merge over global settings; nested objects merge key-by-key rather than replacing wholesale:

// global
{ "theme": "dark", "compaction": { "enabled": true, "reserveTokens": 16384 } }

// project
{ "compaction": { "reserveTokens": 8192 } }

// effective result
{ "theme": "dark", "compaction": { "enabled": true, "reserveTokens": 8192 } }

Edit either file directly, or run /settings in-app for the common options. Some values save from their own UI instead: /model + Ctrl+S saves the startup model, /thinking + Ctrl+S saves the startup thinking level.

3. Resource-loading settings tie the whole system together

These arrays are how you add things from outside Pi's default discovery locations — they're the settings you'll come back to in Lessons 0005–0008:

{
  "extensions": ["/path/to/local/extension.ts"],
  "skills": ["~/.claude/skills"],
  "prompts": ["/path/to/prompts"],
  "packages": ["pi-skills", "npm:@org/my-extension"]
}

Notably: "skills": ["~/.claude/skills"] is how you point Pi at skills written for a different harness — no conversion needed.

4. Keybindings — same shape, different file

~/.pi/agent/keybindings.json rebinds any action by its namespaced id. Format is modifier+key, modifiers combine (ctrl, shift, alt, super), and each action accepts a single key or an array:

{
  "tui.editor.historyPrevious": "ctrl+p",
  "tui.editor.deleteWordBackward": ["ctrl+w", "alt+backspace"]
}

Discover ids with /hotkeys in-app, or check the full action tables in the primary source (editor movement/deletion, session commands, model/thinking cycling, tree navigation, fullscreen transcript scrolling). Ready-made Emacs and Vim binding sets are documented there too if you want a head start.

After editing either file, run /reload to apply changes without restarting the session — no need to quit and relaunch.
