Lesson 0005 · Customization

Skills: on-demand capability packages

A skill is a folder with a SKILL.md describing what it does and when to use it, plus whatever scripts and reference docs it needs. Pi implements the open Agent Skills standard, so skills are portable across harnesses that support it — including ones you may already have from Claude Code.

Why this lesson First of four customization lessons matching the mission's "install and use existing Skills/Extensions/Prompt Templates/Packages, and knows how to write a basic one." Skills are the lowest-friction one to start with — no code required.

1. The core mechanism: progressive disclosure

Pi doesn't load full skill content into context by default. At startup it scans all skill locations and extracts just the name and description from each — those go into the system prompt as a directory. When a task matches a description, the agent uses read (or bash if read is unavailable) to load the full SKILL.md, then follows its instructions. Full content only enters context when it's actually relevant.

This means the description is the entire selection mechanism — vague descriptions mean the skill never gets picked up:

Description
GoodExtracts text and tables from PDF files, fills PDF forms, and merges multiple PDFs. Use when working with PDF documents.
PoorHelps with PDFs.

Discovery rule of thumb: in ~/.pi/agent/skills/ and .pi/skills/, standalone root .md files with valid frontmatter count as skills; everywhere, a directory containing SKILL.md is discovered recursively. Disable auto-discovery entirely with --no-skills (explicit --skill paths still load).

Using skills from Claude Code or Codex directly

No conversion step — just point Pi at the directory:

{
  "skills": ["~/.claude/skills", "~/.codex/skills"]
}

3. Invoking a skill explicitly

Skills auto-register as /skill:name commands. Models don't always self-select a skill even when it matches — force it directly when needed:

/skill:brave-search
/skill:pdf-tools extract

Arguments after the command name append to the skill content as User: <args>. Toggle this registration with enableSkillCommands in settings (default true).

4. Writing a basic skill

my-skill/
├── SKILL.md              # required: frontmatter + instructions
├── scripts/
│   └── process.sh
└── references/
    └── api-reference.md
---
name: my-skill
description: What this skill does and when to use it. Be specific.
---

# My Skill

## Setup

Run once before first use:
```bash
cd /path/to/skill && npm install
```

## Usage

```bash
./scripts/process.sh <input>
```

Reference other files with relative paths from the skill directory — [reference guide](references/REFERENCE.md). Frontmatter fields:

FieldRequiredNotes
nameYes≤64 chars, lowercase a-z/0-9/hyphens, no leading/trailing or consecutive hyphens. Unlike the base standard, Pi does not require this to match the parent directory name.
descriptionYes≤1024 chars — this is what drives selection
licenseNo—
compatibilityNo≤500 chars, environment requirements
allowed-toolsNoSpace-delimited pre-approved tools (experimental)
disable-model-invocationNoIf true, hidden from the system prompt — only reachable via /skill:name

Missing or malformed description/frontmatter produces a warning and the skill doesn't load; most other spec violations warn but still load. Name collisions across locations warn and keep the first one found.

Don't feel obligated to write these by hand. Pi can generate a skill for a workflow you describe — that's often faster and more reliable than authoring frontmatter yourself.

5. Security note

Skills can instruct the model to perform any action, and may include executable code the model invokes directly. Review skill content — yours or third-party — before use, same diligence as reviewing a shell script from the internet.

6. Where to find existing skills

  • Anthropic Skills — document processing (docx/pdf/pptx/xlsx), web development
  • Pi Skills — web search, browser automation, Google APIs, transcription
