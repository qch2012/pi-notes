Lesson 0006 · Customization

Prompt templates: reusable slash-command prompts

The simplest of the four customization surfaces. A prompt template is a single Markdown file; its filename becomes a slash command. If you've written custom slash commands for another agent, this is the same idea with a small, precise argument-substitution syntax.

Why this lesson Second of four customization lessons. This is the one you'll reach for most often day-to-day — it's the fastest way to turn a prompt you keep retyping into a one-word command.

1. The mechanism

review.md becomes /review. That's the whole model. Type / and the template name; autocomplete shows available templates with their descriptions.

---
description: Review staged git changes
---
Review the staged changes (`git diff --cached`). Focus on:
- Bugs and logic errors
- Security issues
- Error handling gaps

description is optional — if omitted, the first non-empty line is used instead. Add argument-hint to show expected arguments in autocomplete (<required>, [optional]):

---
description: Review PRs from URLs with structured issue and code analysis
argument-hint: "<PR-URL>"
---

Which renders in autocomplete as:

→ pr   <PR-URL>       — Review PRs from URLs with structured issue and code analysis
  is   <issue>        — Analyze GitHub issues (bugs or feature requests)
  wr   [instructions] — Finish the current task end-to-end

2. Where they live

LocationScope
~/.pi/agent/prompts/*.mdGlobal
.pi/prompts/*.mdProject — only after trust
Packagesprompts/ dirs or pi.prompts in package.json
settings.json prompts arrayAny files or directories
--prompt-template <path>CLI, repeatable

Discovery in a prompts/ directory is non-recursive — templates in subdirectories need to be added explicitly via the prompts setting or a package manifest. Disable auto-discovery with --no-prompt-templates.

3. Argument substitution

SyntaxMeaning
$1, $2, ...Positional arguments
$@ or $ARGUMENTSAll arguments joined
${1:-default}Arg 1 if present/non-empty, else default
${@:-default} / ${ARGUMENTS:-default}All args if present, else default
${@:N}Args from the Nth position (1-indexed)
${@:N:L}L args starting at N
---
description: Create a component
---
Create a React component named $1 with features: $@
/component Button "onClick handler" "disabled support"

Defaults are handy for optional trailing arguments:

Summarize the current state in ${1:-7} bullet points.

4. Usage examples

/review                           # expands review.md as-is
/component Button                 # expands with $1 = Button
/component Button "click handler" # $1 = Button, $2 = "click handler"
