Lesson 0008 · Customization

Packages: installing bundles of extensions, skills, prompts, and themes

A Pi package is just npm or git carrying one or more of the three resource types from the last three lessons (plus themes). This lesson is about consuming packages — publishing your own is out of scope for now, per the mission.

Why this lesson Last of four customization lessons. This is how the "restoring omitted defaults" table from Lesson 0007 becomes a one-line install instead of an afternoon of writing extensions yourself.

1. Install / manage commands

pi install npm:@foo/bar@1.0.0
pi install git:github.com/user/repo@v1
pi install https://github.com/user/repo      # raw URLs also work
pi install /absolute/path/to/package
pi install ./relative/path/to/package

pi remove npm:@foo/bar
pi list                     # installed packages from settings
pi update                   # update pi itself
pi update --all             # update pi, packages, and reconcile pinned git refs
pi update npm:@foo/bar      # update just one package

By default, install/remove write to global settings (~/.pi/agent/settings.json). Add -l to write to project settings instead (.pi/settings.json) — useful for team-shared config, since Pi auto-installs any missing project-configured packages on startup once the project is trusted.

To try before installing, run ephemeral for one session:

pi -e npm:@foo/bar
pi -e git:github.com/user/repo

Versioned npm specs and git refs are pinned — pi update --extensions/--all won't silently move you to a newer version. To bump a pinned git ref deliberately: pi install git:host/user/repo@new-ref.

3. Filtering what a package loads

Object form in settings narrows a package down to specific resources:

{
  "packages": [
    "npm:simple-pkg",
    {
      "source": "npm:my-package",
      "extensions": ["extensions/*.ts", "!extensions/legacy.ts"],
      "skills": [],
      "prompts": ["prompts/review.md"]
    }
  ]
}

Omit a key to load all of that type; [] loads none; !pattern excludes; +path/-path force-include/exclude an exact path.

4. Enabling/disabling installed resources interactively

pi config       # toggle resources from installed packages/local dirs; Tab switches global/project
pi config -l    # start in project overrides, with inherited global resources dimmed

5. Security note (same bar as extensions)

Pi packages run with full system access. Extensions execute arbitrary code, and skills can instruct the model to perform any action including running executables. Review source code before installing third-party packages.

Treat pi install like npm install from an unfamiliar registry — check what you're pulling in before it runs.

6. Finding packages

The package gallery lists community packages tagged pi-package. Check there before hand-rolling an extension for something common — bridging in MCP, restoring a to-do tool, permission gating — since it's likely already packaged.
