The six deltas, one more time

Worth having memorized cold, since these are the ones most likely to bite mid-task if you're on autopilot from another agent:

  1. No built-in MCP — bridge it via an extension, or find a package that already does.
  2. No sub-agents — ctx.newSession()/ctx.fork() from an extension if you need nested runs.
  3. No permission popups — bash and friends run without a per-call confirm. Add a tool_call extension if you want gating back.
  4. No plan mode — nothing stops the agent from just starting; if you want a plan-then-execute gate, that's a before_agent_start or custom-tool extension.
  5. No to-do/task tracking — same story, stateful custom tool.
  6. No background bash — a shell command runs in the foreground of the tool call; long-lived background process management needs a custom tool.

None of these are gaps you're stuck with — they're defaults, and every one of them is addable in an afternoon or less as an extension, or possibly already exists as a package (0008). The design bet Pi is making is that most sessions don't need all six, so they shouldn't cost context and complexity by default.

Quick self-test

If you can do the following from memory, you're fluent enough to stop referring to these lessons for daily work:

  • Start Pi in a project, switch models, and name the session
  • Go back to an earlier point in a conversation and try a different approach without losing the original path
  • Explain, without checking, what happens to your data if you decline project trust on a repo
  • Point Pi at an existing skill directory from another harness
  • Write and load a one-file extension that blocks a specific dangerous command

If any of those feel shaky, that's a pointer to which numbered lesson to reread — not a reason to keep re-reading all of them front to back.
